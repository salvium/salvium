# Testing the DeFi core

Three layers, all reproducible: unit tests (consensus rules in isolation), regtest end-to-end
(real daemon, real wallet, real oracle process), and the negative tests that prove the guards
actually fire.

## Unit tests

`tests/unit_tests/pricing_record.cpp` - 13 active tests, all passing:

    unit_tests --gtest_filter=pricing_record.*

| test | pins |
|---|---|
| `verify_serialization` | binary round trip of every field |
| `sign_then_verify_roundtrip` | EC P-256 sign/verify with the FAKECHAIN key (helper `a32_make_test_keypair`) |
| `verify_golden_vector_from_external_producer` | byte-exact signing message |
| `verify_accepts_sha1_and_dsa_production_style_vectors` | **DSA-2048/q-224 and EC-P256 SHA-1 signatures must verify** (production key type + legacy digest), plus a tampered-message control |
| `valid_accepts_a_record_the_fakechain_oracle_signed_for_this_block` | happy path of `valid()` |
| `valid_rejects_a_record_signed_for_another_block_height` | height binding (height-1 and height+1) |
| `height_binding_can_be_activated_after_legacy_blocks` | activation-height semantics (`0`, `1000`, `1004`) |
| `valid_pins_the_empty_record_behaviour_and_the_pre_oracle_hf` | empty record accepted, pre-v14 non-empty rejected |
| `valid_rejects_any_record_shaped_payload_that_was_not_signed` | "record-shaped but unsigned" payloads cannot sneak through |
| `an_empty_record_prices_no_conversion` | an empty record makes `get_conversion_rate` fail; a signed record with prices yields `rate == COIN` |
| `valid_rejects_a_tampered_or_foreign_signature` | field tampering, bit flip, foreign key |
| `valid_pins_the_timestamp_window` | future bound, stale bound, strict monotonicity |
| `height_binding_height_is_wired_to_the_network_config` | constants and FAKECHAIN key wiring |

The DSA vectors are golden: `tests/unit_tests/pricing_record.cpp` embeds a PEM public key and
two signature hex strings generated by a small OpenSSL program (`/tmp/dsagolden.cpp` on the dev
machine, links the project's OpenSSL). The test proves the daemon's verifier accepts the
production key type with the legacy digest - without needing DSA key generation at test time.

The signing tests also embed the **regtest (FAKECHAIN) oracle private key**: its public half is
already a consensus constant (`src/cryptonote_config.h:386`), the key exists only for the devnet,
and the daemon has no signing path. It must never be reused for a public network; production keys
stay with the oracle service (or an HSM) and never enter this repository.

### Mutation checks (prove the tests are not vacuous)

Each mutation was applied, the suite rebuilt and run, then the file restored (md5 verified) and
rebuilt green again:

| mutation | expected | observed |
|---|---|---|
| disable the height-binding gate | height tests fail | 2 failed |
| `empty()` always true | unsigned-payload test fails | 5 failed |
| `ma()` returns 1 for a missing asset | empty-record pricing test fails | 1 failed |
| remove SHA-1 from the accepted digests | DSA/SHA-1 golden test fails | 1 failed |

## Regtest end-to-end

Infrastructure (`/Volumes/PMDATA/salvium-dev`): node0 (`--regtest --keep-fakechain
--fixed-difficulty 1`, RPC 28101), a second node as peer (p2p 28130), `salvium-wallet-rpc` on
28230, oracle `python3 devnet/oracle_service.py --keydir /tmp/c5key --port 8443`.

Scripts used during development (kept on the dev machine):

| script | what it does |
|---|---|
| `/tmp/bind_test.sh` | restart node -> mine (positive) -> swap in a height-1 oracle -> assert rejection -> restore -> mine |
| `/tmp/plus_test.sh` | same with a height+1 oracle |
| `/tmp/e2e_final.sh` | full CONVERT flow: fund, transfer with `tx_type=4`, assert burnt amount, minted amount, record height vs block height |
| `/tmp/final_state.sh` | last-15-blocks invariant sampler (`pricing_record.height == height`) |
| `/tmp/mutate.sh`, `/tmp/mutate2.sh` | mutation checks above |

Verified end-to-end result (block index 390):

- block `8c6d0ca2e6092639952d6c4b71ec4e4cf0dff17274e9d540f5ca8eaa9303490c`;
- CONVERT tx `2cc568b99a38feb283416a8d87b034eb419eed066eaacfdc47be485ff57bb332`, burning
  `500000 SAL1`;
- mint `484375 SAL` to the return address (`burned - burned/32`);
- `pricing_record.height == 390 == block index`;
- wallet shows the minted amount spendable.

Negative cases, all rejected with the expected log lines:

| case | oracle behaviour | result |
|---|---|---|
| height binding, record signed for H-1 | `oracle_service_off.py` | `Block not accepted`; `Pricing record height: 387, block height: 388` -> `not bound` |
| height binding, record signed for H+1 | `oracle_service_plus.py` | `Block not accepted`; record 386 vs block 385 |
| replay of an old record | re-sent the record of block 378 into block 379 | rejected by the current build (accepted by the pre-fix build - the original vulnerability demo) |

The sampler over blocks 374-390 shows every block's `pricing_record.height` equals its height,
except the historical block 379 (record 378) mined before the rule existed.
